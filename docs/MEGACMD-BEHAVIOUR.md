# Как MEGAcmd ведёт себя на самом деле

Замерено на MEGAcmd 2.5.2.1 экспериментом на выброшенной паре каталогов
(локальный в `/tmp`, облачный `/megaignore-test`) 31 июля 2026 года. Справке
MEGAcmd верить нельзя, поэтому здесь только то, что подтверждено запуском.

## Правила исключения (`.megaignore`)

| Вопрос | Ответ |
|---|---|
| Судьба уже загруженного при добавлении правила | **Остаётся в облаке и замораживается.** Не удаляется |
| Снятие правила обратно | **Конфликт** локальной и облачной копий, синхронизация встаёт на issue |
| Разрешение конфликта из CLI | Невозможно: `sync-issues` умеет только показывать |
| Уезжает ли `.megaignore` в облако | **Никогда** — ни корневой, ни вложенный, даже без `-:.*` |
| Работают ли вложенные `.megaignore` | Да, локально работают |
| Нужен ли перезапуск синхронизации | Нет, правила применяются на лету |
| `-p:` для вложенного пути | Работает |
| Валидация синтаксиса | Есть: код возврата **51**, в файл мусор не попадает |
| `-sn:*` против симлинков | Снимает проблемы полностью |
| `DEFAULT` | Наследуется новыми синхронизациями, существующие не трогает |
| Кодировка файла | UTF-8 **с BOM** |

### Следствия для интерфейса

**Опасно не добавление правила, а снятие.** Поставить исключение безопасно:
данные не пропадают, файлы просто выпадают из области синхронизации. А вот
вернуть исключённое обратно — это столкновение копий, которое придётся
разбирать руками, файл за файлом. Предупреждать надо на снятии.

**Писать в `.megaignore` напрямую нельзя** — из-за BOM. Всё через
`sync-ignore`, и тогда валидация достаётся бесплатно.

**Двоеточие в фильтре обязательно.** Полная форма —
`<CLASS><TARGET><TYPE><STRATEGY>:<PATTERN>`, и при опущенных цели, типе и
стратегии остаётся `:PATTERN`. Стоковые правила хранятся как `-:~*`; если снять
знак класса и передать `~*` без двоеточия, MEGAcmd отвергнет фильтр.

**Правила не путешествуют вместе с папкой.** На другой машине их даёт либо
профиль `DEFAULT`, либо `.megaignore`, положенный в git репозитория.

### Профиль для новых синхронизаций

`sync-ignore --show DEFAULT` показывает набор, который копируется в каждую
**новую** синхронизацию в момент её создания. Проверено: маркерное правило,
добавленное в `DEFAULT`, появилось у созданной после этого синхронизации и не
появилось у существующей.

Отсюда единственный способ создать синхронизацию, которая сразу работает по
нужным правилам: записать набор в `DEFAULT` и следом создать папку. У команды
`sync` нет флага «создать выключенной», поэтому иначе между созданием и
настройкой остаётся окно, за которое успевает уехать мусор.

## Состояния синхронизации

**Колонка `STATUS` у остановленной синхронизации не меняется.** После
`sync -p` строка выглядит так:

```
yGA51CaUI_Y | /home/user/Projects/ | /Projects | Disabled | Processing | NO
```

`RUN_STATE=Disabled`, а `STATUS` так и остался `Processing` с момента останова.
Судить о работе надо по `RUN_STATE`, иначе интерфейс крутит спиннер у
остановленной папки.

## Передачи

**`transfers` по умолчанию скрывает передачи синхронизаций** — для них нужен
`--show-syncs`. Без него при заливке 15 ГБ список передач остаётся пустым.

**`transfers --summary`** отдаёт сводные проценты по загрузке и выгрузке —
готовый источник для индикатора прогресса. Разделитель колонок игнорирует, как
`fuse-show`, поэтому значения разбираются по пробелам после склейки числа с
единицей («0.00   B» → «0.00B»).

## Публичные ссылки

`export /` печатает все действующие ссылки дерева:

```
/путь/файл.pdf (90.92 KB, shared as exported permanent file link: https://mega.nz/file/…)
/путь/папка (folder, shared as exported permanent folder link: https://mega.nz/folder/…)
```

Имя файла может содержать « (», поэтому границу пути искать надо не первой
скобкой, а последней перед фиксированной меткой `, shared as exported`.

`export -d <путь>` отзывает ссылку. Операция необратима: заново созданная
ссылка получает другой ключ, и старая не оживёт.

## Чего в MEGAcmd нет

- **Израсходованного трафика.** `whoami -l` отдаёт объём хранилища, уровень Pro,
  историю покупок и сессии — цифр по трафику нет вовсе. Смотреть только в
  веб-интерфейсе.
- **Истории синхронизаций.** Только снимок текущего момента.
- **Разрешения конфликтов.** См. выше.
- **`--col-separator` у `df`, `whoami`, `sync-config`, `backup`, `fuse-show`.**
  У `fuse-show` флаг указан в справке, но отвергается.

## Стоимость опроса

Замерено по приросту процессорного времени `mega-cmd-server` за 20 циклов:

| Что | Расход |
|---|---|
| Лёгкий цикл (`df`, `sync`, `transfers`, `sync-issues`) | 52 мс CPU сервера |
| `whoami -l` | 170 мс |
| `fuse-show` | ~0 |
| `export /` (76 тысяч узлов) | 480 мс |
| Сам сервер в простое, без наших команд | **0,33 % одного ядра** |

Отсюда расход виджета: 0,029 % ядра при опросе раз в 180 секунд (на батарее),
0,17 % при 30 секундах, 2,6 % при открытом попапе. То есть на батарее виджет
добавляет примерно девятую часть того, что сервер тратит, ничего не делая.

Вывод для проектирования: дорогие обходы дерева (`export /`) в цикл опроса не
ставить, вызывать по открытию соответствующей вкладки.
