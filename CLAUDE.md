# Правила работы с этим плазмоидом

Документ для Claude Code. Здесь собрано то, что было выяснено экспериментально и
стоило времени. Всё перечисленное проверено на Plasma 6.7 и подтверждено либо
исходниками plasma-workspace, либо замерами.

**Общие правила интерфейса плазмоидов, не привязанные к этому проекту, вынесены
в [docs/PLASMOID-UI-GUIDELINE.md](docs/PLASMOID-UI-GUIDELINE.md)** — там метрики,
каталог компонентов, ловушки раскладки, требования к уведомлениям и локализации,
способы проверки и чек-лист. Ниже — только то, что специфично для этого виджета.

## Главное правило

**Не подбирать вид на глаз — брать метрики из исходников системного виджета.**
Эталон для попапа трея: `applets/devicenotifier/qml/FullRepresentation.qml` в
plasma-workspace. Скачивается так:

```sh
curl -s "https://invent.kde.org/plasma/plasma-workspace/-/raw/master/applets/devicenotifier/qml/FullRepresentation.qml"
```

Список файлов любого аплета — через API GitLab:

```sh
curl -s "https://invent.kde.org/api/v4/projects/plasma%2Fplasma-workspace/repository/tree?path=applets%2Fsystemtray%2Fqml&per_page=100"
```

Каждая правка «чтобы выглядело нативно» без ссылки на конкретный файл эталона —
это угадывание, и оно уже трижды приводило к переделке.

## Интеграция с системным треем

**Аплет НЕ объявляет свой `header`.** Трей рисует общую шапку сам
(`applets/systemtray/qml/ExpandedRepresentation.qml`): стрелка «назад», название
из `plasmoid.title`, кнопки действий с `priority === PlasmaCore.Action.HighPriority`,
«гамбургер» `application-menu` с остальными действиями, шестерёнка настроек,
булавка. Свой `header` трей подклеивает **второй строкой** под своей:

```qml
height: trayHeading.height + bottomPadding + container.headingHeight
```

Отсюда двойной заголовок и высота, не совпадающая с батареей, сетью и звуком.

Кнопки, которые должны быть в шапке, объявляются так:

```qml
Plasmoid.contextualActions: [
    PlasmaCore.Action {
        text: i18n("Pause updates")
        icon.name: "media-playback-pause"
        priority: PlasmaCore.Action.HighPriority   // прямая кнопка в шапке трея
        checkable: true
        checked: backend.paused
        onTriggered: root.togglePause()
    },
    PlasmaCore.Action {
        text: i18n("Open MEGA folder")            // без priority → в «гамбургер»
        icon.name: "folder-open"
        onTriggered: /* ... */
    }
]
```

Размеры: попап трея сам держит минимум `Kirigami.Units.gridUnit * 24` на обе
стороны. Запрашивать больше нельзя — виджет станет выше соседей, и переключение
между виджетами перестанет быть бесшовным.

## Метрики

| Что | Значение | Единица |
|---|---|---|
| Боковые отступы содержимого | `Kirigami.Units.largeSpacing` | 8 px |
| Шаг между элементами | `Kirigami.Units.smallSpacing` | 4 px |
| `Kirigami.Units.gridUnit` | 18 px | **для отступов не годится** |

`gridUnit` в отступах даёт поля вдвое шире нативных. Это была одна из первых
претензий пользователя и она оказалась ровно про это.

## Компоненты

Использовать штатные, ручную вёрстку — нет. Иначе разъезжаются высота строк,
отступы и кегль.

| Задача | Компонент |
|---|---|
| Корень раскрытой панели | `PlasmaExtras.Representation` |
| Прокрутка | `PlasmaComponents.ScrollView` (не `QQC2.ScrollView`), горизонтальная полоса `AlwaysOff` |
| Строка списка | `PlasmaExtras.ExpandableListItem` |
| Второстепенный текст | `PlasmaExtras.DescriptiveLabel` (не `Label` с уменьшенным шрифтом и `opacity`) |
| Пустое состояние | `PlasmaExtras.PlaceholderMessage` |
| Сообщение в панели | `Kirigami.InlineMessage` |
| Нижняя панель с кнопками | `footer: PlasmaExtras.PlasmoidHeading { position: PlasmaComponents.ToolBar.Footer }` |
| Заголовок секции | **свой `SectionHeader.qml`**, см. ниже |

### Никакого полужирного текста

Требование пользователя: полужирного в виджете быть не должно, но названия
секций нужны. Поэтому `PlasmaExtras.ListSectionHeader` **не используется** — он
рисует подпись через `Kirigami.Heading` с зашитым `font.weight: Font.Bold`, и
снаружи это не переопределяется. Вместо него `contents/ui/SectionHeader.qml`:
та же геометрия, кегль и линия, начертание `Font.Normal`.

При копировании оттуда есть грабля: в оригинале у подписи стоит
`Layout.maximumWidth: rowLayout.width`, и это законно только потому, что строка
лежит внутри `ItemDelegate` и получает ширину извне. Если корнем компонента
сделать сам `RowLayout` (элемент внешней раскладки), получается
`Qt Quick Layouts: Detected recursive rearrange`. Правильно —
`Layout.minimumWidth: 0` плюс `elide`.

### ListView внутри ColumnLayout

Обязателен `implicitHeight: contentHeight`, а не только `Layout.preferredHeight`:

```qml
ListView {
    implicitHeight: contentHeight          // без этого раскладка считает список нулевым
    Layout.preferredHeight: contentHeight
    interactive: false
    currentIndex: -1                       // иначе Highlight висит на первой строке
    highlight: PlasmaExtras.Highlight {}
}
```

Замерено: без `implicitHeight` список отдаёт `h=0` при видимых строках (делегаты
рисуются за пределами границ, потому что `clip` выключен), место под него не
резервируется, и нижние секции наезжают друг на друга.

`ExpandableListItem` внутри обращается к `ListView.view`, поэтому обязан жить в
настоящем `ListView`, а не в `Repeater` — иначе краш при раскрытии строки.

### Ловушки размеров

- `ScrollView` с `contentWidth: availableWidth` внутри `Representation` даёт
  binding loop по `implicitWidth`. Лечится явным `implicitWidth` у ScrollView.
- Высоту панели считать от содержимого, а не задавать жёстко:
  `Math.min(content.implicitHeight + отступы + footer.height, gridUnit * 24)`.
  Жёсткое значение оставляет пустоту вне трея; ограничение сверху не даёт стать
  выше соседей; переполнение уходит в прокрутку.

## Согласованность интерфейса

Одинаковое действие — один компонент и одна подпись. Было: две кнопки
«Open local folder» и «Open in file manager», делавшие один и тот же
`xdg-open`. Стало: `OpenFolderAction.qml` плюс `Backend.openLocal()`.

Прежде чем добавлять действие, поискать, нет ли уже такого же.

## Backend и запуск процессов

Весь доступ к MEGAcmd и к процессам — только в `contents/ui/Backend.qml`.
`Plasma5Support` это модуль совместимости, KDE его однажды выпилит; когда это
случится, переписать нужно будет один файл.

### Экранирование команд

**Команду для `DataSource` нельзя оборачивать в `JSON.stringify`.** При
`sh -c "..."` аргументы теряются молча: команда выполняется, код возврата 0,
переменные внутри пустые. Из-за этого тихо не работали чтение размера кэша,
очистка кэша и открытие папок.

Правильно — одинарные кавычки с экранированием по схеме `'\''`:

```qml
function quote(s) {
    return "'" + String(s).replace(/'/g, "'\\''") + "'";
}
function sh(script, cb, timeoutMs) {
    exe.run("sh -c " + quote(script), cb, timeoutMs);
}
```

Двойные кавычки для значений непригодны: внутри них шелл раскрывает `$` и
`` ` ``, то есть имя файла вида `a$b.txt` превратится в другое.

### У DataSource нет default property

Дочерний `Timer` внутрь не принимается — `Cannot assign to non-existent default
property`, и виджет вообще не грузится. Сторож очереди объявлен снаружи.

### Очередь

Команды выполняются строго по одной (замерено: 1 процесс `mega-exec`
одновременно вместо 5–8 при параллельном запуске). FIFO, дедупликация одинаковых
команд (естественный тормоз, если очередь не поспевает за таймером), таймаут на
команду: 15 с по умолчанию, 180 с у `clearCache`. Оговорка:
`disconnectSource` не убивает процесс, зависшая команда остаётся сиротой.

## Экономия батареи

Требование пользователя: виджет не должен заметно тратить заряд.

- Адаптивный интервал: раскрыто 2 с, свёрнуто от сети 30 с, от батареи 180 с.
- Тяжёлые вызовы (`whoami -l`, `fuse-show`, `du` кэша) — раз в 10 циклов.
- Пауза (`Plasmoid.configuration.paused`) полностью останавливает таймер: ни
  процессов, ни пробуждений. Данные только по кнопке.
- На паузе `Plasmoid.status` не должен быть `NeedsAttention`: данные заведомо
  могут быть устаревшими, поднимать по ним тревогу нельзя.

Для справки: сам `mega-cmd-server` в простое ест 0,6 % CPU и 568 МБ RSS, то есть
виджет на его фоне — шум. Настоящий пожиратель заряда — превьюшки Dolphin,
качающие файлы через FUSE-маунт.

## Особенности MEGAcmd

Справке MEGAcmd верить нельзя, каждую команду проверять запуском.

- `--col-separator` и `--output-cols` работают у `sync`, `transfers`,
  `sync-issues`. У `df`, `whoami`, `sync-config`, `backup` их нет.
- **`fuse-show` указывает `--col-separator` в своей справке, но отвергает его** —
  для него написан парсер по ширине колонок.
- Разбирать таблицы по именам колонок из заголовка, а не по позициям: смена
  версии MEGAcmd тогда не сломает виджет.
- Израсходованный трафик из CLI получить нельзя вообще. Не показывать.
- Истории синхронизаций нет, только снимок текущего момента.
- Логин в UI не делать: `mega-exec login email password` светит пароль в `ps`.

## Локализация

Исходные строки в коде — английские. Каталоги в `po/`, компилирует
`po/build-mo.py` (свой генератор `.mo`, без gettext — его нет в системе, и на
Steam Deck ставить некуда). Готовый `.mo` коммитится, чтобы установка
«скопировал каталог — работает» ничего не собирала.

Домен: `plasma_applet_<pluginId>` — формула из
`Plasma::Applet::translationDomain()`. Каталог ищется в
`<XDG data dir>/locale/<язык>/LC_MESSAGES/<домен>.mo`; схема подтверждена 55
системными каталогами в `/usr/share/locale/ru/LC_MESSAGES/plasma_applet_*.mo`.

Сверять каталог с исходниками **по паре (msgctxt, msgid)**, а не по одному
msgid: при поиске перевода контекст входит в ключ, поэтому одинаковый текст с
разными контекстами — разные записи. `build-mo.py` это учитывает и печатает
непереведённые и лишние строки.

**Перевод нельзя проверить в стенде `qml6`** — домен подключает только Plasma при
загрузке аплета, вне неё строки остаются английскими
(`kf.i18n: Domain is not set`). Проверять только в реальной оболочке.

## Файлы вне пакета

Пакет плазмоида ставит файлы только внутрь себя, а два файла обязаны лежать по
стандартным путям XDG:

- `~/.local/share/knotifications6/<домен>.notifyrc` — без него KNotification
  молчит, а в Параметрах системы не появляется раздел для настройки уведомлений;
- `~/.local/share/locale/<язык>/LC_MESSAGES/<домен>.mo` — каталог переводов.

Поэтому оба едут внутри пакета, а `Backend.installRuntimeFiles()` копирует их на
место при запуске (сравнение через `cmp`, копирование только при отличии). На
новой машине всё заработает само, без установочных скриптов.

## Уведомления

Типы событий описываются в `.notifyrc`; имя файла обязано совпадать с
`componentName`. Срабатывать они должны **по фронту** состояния, иначе одна и та
же проблема сыпется каждый цикл опроса. Данные приходят несколькими
асинхронными вызовами, поэтому проверка идёт с дебаунсом (1,5 с), а первый
проход только запоминает состояние — при добавлении виджета не нужно вываливать
уведомления о том, что и так видно в панели.

Информационные события (`cacheBloated`, `syncFinished`) объявлены с пустым
`Action=` — по умолчанию выключены, но в Параметрах системы видны.

## Настройки

Диалог из двух страниц: `configGeneral.qml` — настройки виджета,
`configFolders.qml` — управление синхронизациями и маунтами.

**У страницы «Папки» нет ни одного свойства `cfg_*`, и это правильно.** Она
меняет состояние сервера MEGAcmd, а не конфигурацию виджета, поэтому операции
применяются сразу, а не по кнопке «Применить». Проверка совпадения ключей в CI
смотрит только на `configGeneral.qml`.

Страница настроек живёт в отдельном контексте и **не видит `Backend` виджета** —
у неё свой экземпляр с `paused: true` (опрос по таймеру там не нужен, данные
обновляются после каждой операции). Компоненты из `contents/ui/` ей доступны:
страницы лежат в том же каталоге.

Ключи в `contents/config/main.xml` обязаны совпадать с алиасами `cfg_*` в
`configGeneral.qml`. При расхождении диалог открывается, но значения молча не
сохраняются — это проверяет CI.

Форма — `Kirigami.FormLayout`: подписи с двоеточием в левой колонке, единицы
измерения **в подписи**, а не внутри `SpinBox` через `textFromValue` (иначе
ломается ввод с клавиатуры), смысловые группы через
`Kirigami.FormData.isSection` с заголовком.

## Как проверять сделанное

### Вывод QML не виден без переменной окружения

```sh
QT_FORCE_STDERR_LOGGING=1 qml6 файл.qml
```

Без неё лог **пуст даже при фатальных ошибках**, и пустота выглядит как успех.
На этом уже трижды были ложные доклады «ошибок нет».

### Стенд

`plasmawindowed` показывает ошибки загрузки в GUI-диалоге, а не в stdout, и его
код выхода ничего не доказывает. Проверять стендом:

```qml
// contents/ui/_d.qml — временный, в .gitignore
import QtQuick
import QtQuick.Window
import QtQuick.Layouts
Window {
    visible: true
    width: Math.round(rep.Layout.preferredWidth)
    height: Math.round(rep.Layout.preferredHeight)
    Backend { id: be; paused: false; expanded: true }
    FullRepresentation { id: rep; anchors.fill: parent; backend: be }
    Timer { interval: 20000; running: true; onTriggered: Qt.quit() }
}
```

Правила:
- модели наполнять данными, иначе делегаты не создаются и их ошибки не всплывут;
- стенд должен сам вызывать `Qt.quit()` — `SIGTERM` от `timeout` теряет буферы;
- признак поломки: код выхода 2 и «Did not load any objects»; код 124 (таймаут)
  означает, что объекты создались и живут;
- искать в логе `Binding loop`, `recursive rearrange`, `TypeError`,
  `Cannot assign`.

### В стенде нельзя судить о цветах

Без темы оболочки компоненты Plasma рисуются дефолтными цветами: `ItemDelegate`
выглядит голубым, кнопки тёмной заливкой (легко принять за обрезанные). В стенде
судить только о геометрии, и лучше по числам, а не по картинке. Цвета и шрифты —
только в реальной оболочке.

### Геометрию мерить, а не смотреть

```qml
console.warn("content implicitH=" + Math.round(content.implicitHeight)
             + " rep.h=" + Math.round(rep.height));
for (var i = 0; i < content.children.length; ++i) { /* y, height, implicitHeight */ }
```

## Установка и сборка

**Нельзя `kpackagetool6 -u <каталог>`, если каталог сам является местом
установки** — он удаляет пакет перед переустановкой из него же и оставляет
пустоту. Поэтому исходники отделены от места установки, а `make install`
копирует.

После правки QML нужен перезапуск оболочки, иначе Plasma отдаёт закэшированное:

```sh
kquitapp6 plasmashell && kstart plasmashell
```

Передобавлять виджет в панель при этом не нужно: пока `Id` в `metadata.json` не
менялся, существующий экземпляр подхватит новые файлы.

## Отчётность

Пользователь дважды ловил на докладах об успехе, которого не было. Поэтому:

- не писать «проверено», если проверка сводилась к пустому логу;
- код выхода `timeout` (124) — не доказательство работоспособности;
- если что-то не проверено (вид в реальной оболочке, поведение на Steam Deck) —
  говорить это прямо;
- при обнаружении собственной ошибки исправлять и называть её, а не
  переформулировать.

## Репозиторий

- Публикация: `github.com/metallcorn/megaplasmoid`, отправка деплой-ключом через
  host-алиас `github.com-megaplasmoid`.
- Версию в `metadata.json` держать в согласии с тегом: `release.yml` это
  проверяет и отказывается собирать релиз при расхождении.
- CI (`check.yml`) проверяет валидность метаданных, совпадение ключей настроек,
  полноту переводов, свежесть закоммиченного `.mo` и синтаксис QML. Перед
  коммитом стоит прогнать `python3 po/build-mo.py` — он и есть проверка
  переводов.
- Комментарии в коде русские, интерфейс и README английские. Если репозиторий
  пойдёт в KDE Store и появятся сторонние участники, комментарии стоит перевести.
